# 安全威胁模型分析

## ECH + Kyber + TLS 1.3 协议套件的安全分析

---

## 1. 概述

本文档分析 Kiwi Browser 网络协议扩展的威胁模型，
涵盖 ECH、Kyber、TLS 1.3 0-RTT、HTTP/3 等协议的安全属性、
潜在攻击面及其缓解措施。

### 信任假设

| 组件 | 信任等级 | 说明 |
|------|----------|------|
| 用户设备 (Android) | ✅ 可信 | 假设设备未被恶意软件入侵 |
| Kiwi Browser 进程 | ✅ 可信 | 代码未被篡改 |
| 网络服务进程 | ✅ 可信 | Chromium 沙箱保护 |
| DNS 服务器 (DoH) | ⚠️ 半可信 | 加密传输但可能记录日志 |
| 目标网站服务器 | ⚠️ 半可信 | 可能被攻陷 |
| 网络中间盒 | ❌ 不可信 | 路由器、防火墙、ISP |
| CA 证书颁发机构 | ⚠️ 半可信 | 可能被攻陷或滥用 |

## 2. 威胁分析与缓解

### 2.1 ECH (Encrypted ClientHello)

| 威胁 | 描述 | 严重性 | 缓解措施 |
|------|------|--------|----------|
| **T1: SNI 泄露** | 中间人读取 ClientHello 中的 SNI，知道用户访问的网站 | 🔴 高 | ECH 加密 SNI 字段 |
| **T2: ECH 降级攻击** | 攻击者移除 ECH 扩展，迫使回退明文 SNI | 🔴 高 | ECH GREASE + ECHDegradationMonitor 检测 |
| **T3: ECH 重放攻击** | 攻击者重放 ECH ClientHello 猜测 SNI | 🟡 中 | ECH 每次握手使用新鲜随机数 (BoringSSL 保证) |
| **T4: 指纹攻击** | ECH ClientHello 大小特征识别使用 ECH 的用户 | 🟡 中 | ECH GREASE 填充随机大小 |
| **T5: 重试风暴** | 攻击者反复伪造 retry_config 使客户端无限重试 | 🟢 低 | 最多 3 次重试，之后回退 |
| **T6: 侧信道攻击** | 通过握手时序推断 ECH 是否成功 | 🟢 低 | 随机化重试延迟 |

#### T1 缓解: ECH 加密

```
攻击者视角:
  ClientHello (无 ECH):
    → SNI: example.com  ← 明文可见

  ClientHello (有 ECH):
    → 加密载荷           ← 仅服务器可解密
    → SNI: 无            ← SNI 字段被删除

即使攻击者拥有网络全流量访问权限，
也无法从 ECH 加密的 ClientHello 中提取 SNI。
```

#### T2 缓解: 降级检测

```python
# ECHDegradationMonitor 检测逻辑
if (连续 ECH 失败次数 >= 5) 或
   (总尝试 >= 10 且 成功率 < 30%):
    触发降级告警
    可能原因:
      - 中间人移除 ECH 扩展 (攻击)
      - 服务器 ECH 配置过期 (非攻击)
    处理:
      - 回退明文 SNI
      - 上报 UMA 指标
      - 72 小时后重试
```

### 2.2 Kyber 后量子密钥交换

| 威胁 | 描述 | 严重性 | 缓解措施 |
|------|------|--------|----------|
| **T7: 先存储后解密** | 攻击者记录 TLS 握手，等量子计算机成熟后解密 | 🔴 高 | Kyber768 提供抗量子安全性 |
| **T8: Kyber 实现缺陷** | Kyber 实现中的侧信道泄露密钥 | 🟡 中 | 使用 BoringSSL 经过审计的实现 |
| **T9: 混合降级** | 攻击者移除 Kyber 组，强制使用仅 X25519 | 🟡 中 | 验证握手使用的组; 记录告警 |
| **T10: 大 ClientHello DoS** | Kyber 增加 ~1KB ClientHello，可能用于放大攻击 | 🟢 低 | 限制 ClientHello 最大大小 |

#### T7 缓解: 混合密钥协商

```
传统 ECDHE (X25519):
  客户端密钥 → 服务器密钥 = 会话密钥
  攻击者记录握手 → 量子计算机破解 → 解密历史流量  ← 危险!

X25519 + Kyber768 混合:
  客户端密钥1 → 服务器密钥1 = X25519 共享密钥
  客户端密钥2 → 服务器密钥2 = Kyber768 共享密钥
  会话密钥 = HKDF(X25519_shared || Kyber768_shared)

  攻击者需要同时破解:
    - X25519 (传统 ECDLP)
    - Kyber768 (基于格)
  量子计算机只能破解 X25519，无法破解 Kyber768
```

### 2.3 TLS 1.3 0-RTT Early Data

| 威胁 | 描述 | 严重性 | 缓解措施 |
|------|------|--------|----------|
| **T11: 0-RTT 重放** | 攻击者重放 0-RTT 数据导致副作用 (如重复下单) | 🔴 高 | 幂等性检查; 仅允许 GET 请求 |
| **T12: 0-RTT 前向安全** | 长期密钥泄露可解密 0-RTT 数据 | 🟡 中 | 0-RTT 数据不含敏感操作 |

#### T11 缓解: 幂等性限制

```cpp
// 0-RTT 仅允许幂等请求
bool CanUse0Rtt(const HttpRequestInfo& request) {
  // 仅允许 GET/HEAD/OPTIONS
  switch (request.method) {
    case "GET":
    case "HEAD":
    case "OPTIONS":
      return true;
    default:
      return false;  // POST/PUT/DELETE 不走 0-RTT
  }
}
```

### 2.4 DNS over HTTPS (DoH)

| 威胁 | 描述 | 严重性 | 缓解措施 |
|------|------|--------|----------|
| **T13: DoH 服务商监控** | DoH 提供商记录用户的 DNS 查询 | 🟡 中 | 预置多个提供商; 用户可自定义 |
| **T14: DoH 阻断** | 防火墙封锁 DoH 端点 (如 cloudflare-dns.com) | 🟡 中 | 自动回退到系统 DNS |
| **T15: DNS 缓存投毒** | 攻击者伪造 DNS 响应注入恶意 HTTPS 记录 | 🟡 中 | DNSSEC 验证; DoH 加密传输 |

### 2.5 HTTP/3 (QUIC)

| 威胁 | 描述 | 严重性 | 缓解措施 |
|------|------|--------|----------|
| **T16: UDP 放大攻击** | QUIC 服务器作为放大攻击的反射器 | 🟡 中 | QUIC 内置源地址验证 |
| **T17: 连接迁移劫持** | 攻击者伪造迁移包接管 QUIC 连接 | 🟡 中 | 迁移路径验证 (PATH_CHALLENGE) |
| **T18: QUIC 指纹** | QUIC 实现特征可用于设备指纹识别 | 🟢 低 | 随机化 QUIC 参数 |

## 3. 纵深防御

### 3.1 多层保护

```
用户访问 https://example.com

Layer 1: DNS
  ├── DoH 加密查询 → 防 DNS 劫持
  └── DNSSEC 验证 → 防 DNS 投毒

Layer 2: 连接
  ├── QUIC (UDP) 或 TCP
  ├── 连接迁移保护 → 防中间人劫持
  └── 源地址验证 → 防放大攻击

Layer 3: TLS 握手
  ├── ECH → 加密 SNI (防嗅探)
  ├── Kyber + X25519 → 混合密钥 (抗量子)
  ├── 扩展排列 → 防 ossification
  └── 证书验证 → 防中间人

Layer 4: 数据传输
  ├── TLS 1.3 加密 → 防窃听
  ├── Key Update → 定期更新密钥
  └── HTTP/3 QPACK → 防压缩侧信道
```

### 3.2 失败回退链

```
ECH 失败?
  ├── Retry_config 可用 → 重试 (最多 3 次)
  └── 无 retry_config
        ├── 检测到 TLS 拦截? → 禁用 ECH + 告警
        └── 未检测到拦截 → GREASE + 明文 SNI

Kyber 不支持?
  └── X25519 传统 ECDHE (降级)

HTTP/3 不可用?
  ├── QUIC 超时 → TCP + HTTP/2
  └── TCP 失败 → 错误上报

DoH 不可用?
  └── 系统 DNS (UDP 53) 回退
```

### 3.3 告警阈值

| 指标 | 警告 | 严重 | 停用 |
|------|------|------|------|
| ECH 成功率 | < 60% | < 30% | < 10% |
| Kyber 使用率 | < 40% | < 20% | - |
| QUIC 成功率 | < 70% | < 50% | < 20% |
| DoH 可用性 | < 90% | < 70% | < 50% |

## 4. 隐私考量

### 4.1 指纹空间分析

| 协议 | 可识别特征 | 独特度 | 缓解 |
|------|-----------|--------|------|
| ECH | ClientHello 大小 | 🟡 中 | GREASE 填充 (768-2048 字节随机) |
| Kyber | groups_list 顺序 | 🟢 低 | 所有用户使用相同配置 |
| QUIC | 连接参数 | 🟡 中 | 随机化初始参数 |
| HTTP/3 | QPACK 编码表大小 | 🟢 低 | 固定标准值 |

### 4.2 DoH 隐私策略

```
Cloudflare: 不记录 IP, 24h 保留查询日志
Google:     匿名化后 24-48h 保留
Quad9:      不记录 IP, GDPR 合规
阿里云:     遵循中国数据保护法规
```

用户可在 `设置 → 安全 DNS` 中切换提供商或使用自定义服务器。

## 6. 总结

Kiwi 网络协议扩展在四个安全维度上提供了显著增强:

| 维度 | 传统浏览器 | Kiwi 扩展 | 提升 |
|------|------------|-----------|------|
| 🕵️ 隐私 | SNI 明文 | ECH 加密 | 防域名嗅探 |
| 🔮 抗量子 | X25519 仅 | Kyber + X25519 | 防先存储后解密 |
| ⚡ 性能 | TCP + TLS | QUIC + 0-RTT | 减少 2-3 RTT |
| 🔒 韧性 | 单一协议 | 多层回退 | 更高可用性 |
